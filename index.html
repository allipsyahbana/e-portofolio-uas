Siklus 2 — Baris Perintah (CLI) & Struktur Direktori

Model PjBL + Deep Learning, Saintifik, Experiential Learning, CRT (Budaya Banjar) · 1 pertemuan (4×45 menit)

🔍 Analisis Mendalam

Modul dirancang untuk alokasi 1 pertemuan (4×45 menit / 180 menit) pada mata pelajaran Dasar Kompetensi Keahlian Sistem Operasi kelas X PPLG. Mengintegrasikan model Project Based Learning (PjBL) dengan pendekatan Deep Learning, Saintifik, Experiential Learning, dan Culturally Responsive Teaching (CRT). Pembelajaran dibangun di atas skenario proyek otentik "Website Agensi Game & Game 2D Scratch untuk Anak PAUD".

Keunikan utama terletak pada penyisipan nilai budaya lokal Banjar — analogi penataan lapak di pasar terapung dan semangat gotong royong "Kayuh Baimbai" — ke dalam sintaks PjBL tanpa mengubah struktur utamanya. Pengalaman belajar disusun dalam 6 sintaks PjBL dengan alokasi 15 menit awal, 135 menit inti, dan 30 menit penutup.

✅ Kelebihan

  • Integrasi CRT yang Autentik: Membumikan materi CLI yang abstrak melalui analogi kearifan lokal Banjar (pasar terapung) dan prinsip Kayuh Baimbai.
  • Struktur Sintaks PjBL Runtut: Alur terstruktur dari apersepsi kontekstual, pertanyaan mendasar, perencanaan sketsa direktori, hingga unjuk hasil melalui terminal.
  • Kejelasan Orientasi Masa Depan (Scaffolding): Keterampilan CLI Linux diposisikan sebagai fondasi wajib untuk materi Git (M-5) dan GitHub (M-6).

⚠️ Kekurangan

  • Beban Waktu Sintaks 4 Padat: 55 menit untuk 14 langkah tutorial mandiri sekaligus studi kasus; berisiko meleset jika ada kendala teknis VM Ubuntu.
  • Ketergantungan Prasyarat Teknis: Keberhasilan bergantung pada kesiapan VM Ubuntu hasil praktik M-2; masalah spesifikasi laptop (RAM/Storage) akan menghambat praktik.

💭 Refleksi

Merancang modul ini menguji kemampuan saya mengawinkan ketajaman teknis IT dengan pendekatan pedagogis inklusif. Mengajarkan baris perintah kepada siswa kelas X tidak bisa sekadar menyodorkan sintaks hafalan. Mengaitkan logika struktur direktori dengan budaya lokal Banjar terbukti meredam kecemasan siswa terhadap layar hitam terminal. Ke depannya, saya harus menyiapkan plan B (terminal berbasis web/emulator ringan) untuk mengantisipasi kegagalan VM di laboratorium.

🖥️ Media Pembelajaran (PPT & Bahan Ajar)

Media terdiri dari PPT 18 slide dan Bahan Ajar 31 halaman yang saling menguatkan. PPT sebagai visual anchor saat apersepsi dan demonstrasi; Bahan Ajar sebagai handbook mandiri siswa. Memuat konsep CLI vs GUI, arsitektur perintah [opsi] [target], tabel referensi perintah, panduan troubleshooting, cheat sheet, hingga jembatan ke Git/GitHub.

Kelebihan: kelengkapan komponen (cheat sheet, glosarium, tips kerja aman), visualisasi anatomi perintah via diagram warna, serta sikap inklusif terhadap kesalahan (debugging mindset).

Kekurangan: beberapa slide terlalu dominan teks tanpa screenshot terminal nyata; Bahan Ajar 31 halaman berpotensi information overload jika tidak dibimbing bertahap.

📝 LKPD

Dikembangkan sebagai guided lab worksheet dengan 5 bagian: rangkuman materi, tutorial praktikum 14 langkah, studi kasus "Agensi Game Ceria", tabel lembar kerja praktik, dan kuis evaluasi (5 PG + 3 uraian) beserta rubrik dan jurnal refleksi.

Kelebihan: runtutan scaffolding sistematis (pwd → mkdir → copy-move-delete → clear → history); akuntabilitas proses via Lembar Kerja F; studi kasus berbasis masalah nyata.

Kekurangan: langkah 1–14 terlalu preskriptif (cookbook style) sehingga kurang ruang eksplorasi bagi fast learners; penggabungan kuis dalam berkas LKPD berpotensi memecah fokus siswa.

📊 Instrumen Penilaian

Menggunakan triangulasi komprehensif aspek proses dan produk: A1 Ketepatan Perintah (14 langkah), A2 Struktur Folder (8 bagian), A3 Kemandirian/Observasi, A4 Pemahaman Konsep/Kuis. Nilai Akhir = ((A1+A2+A3+A4)/16) × 100. Dilengkapi lembar observasi, checklist produk, kisi-kisi kuis, rubrik esai, dan rekapitulasi nilai.

Kelebihan: rubrik objektif terukur, penilaian berbasis kinerja asli (authentic assessment), pedoman predikat A–D dan skema remedial/pengayaan.

Kekurangan: beban administrasi guru tinggi (memeriksa 14 langkah + 8 komponen folder per siswa secara individual); indikator CRT pada aspek sikap masih implisit dalam A3.

Siklus 3 — Landing Page "Website Agensi PixelPlay" & Version Control

Model PjBL + Deep Learning, Saintifik, CTL · 4 JP × 45 menit (180 menit)

🔍 Analisis Mendalam

Modul dirancang untuk 4 JP × 45 menit (180 menit) dengan model Project Based Learning (PjBL) yang dipadukan dengan Deep Learning, Saintifik, dan Contextual Teaching and Learning (CTL). Sintaks PjBL diadaptasi ke 6 tahapan vokasi: Penentuan Pertanyaan Mendasar, Mendesain Perencanaan, Menyusun Jadwal, Memantau Keaktifan, Menguji Hasil, dan Mengevaluasi Pengalaman.

Pembelajaran berpusat pada skenario otentik industri: pembuatan landing page "Website Agensi PixelPlay". Secara eksplisit mengintegrasikan Dimensi Profil Lulusan (DPL) — Penalaran Kritis, Kemandirian, dan Kolaborasi — melalui metode peer check dan pengelolaan repositori individu.

✅ Kelebihan

  • Sintaks PjBL Terstruktur: Tahapan disesuaikan presisi dengan alur teknis IT, alokasi realistis (15/135/30 menit).
  • Apersepsi Kontekstual & Bermakna: Contoh penamaan file manual yang tidak teratur (website-final-revisi-2-fix) membangun kebutuhan intuitif siswa terhadap Version Control System.
  • Desain Pembelajaran Inklusif: Alur pengayaan (struktur folder CSS/JS) untuk fast learners dan skema tutor sebaya (peer check).

⚠️ Kekurangan

  • Ketidaksesuaian Identitas Administratif: Dokumen tercantum Kelas X PPLG / Fase E, sementara pelaksanaan perlu disesuaikan dengan target mengajar (Kelas XI PPLG).
  • Risiko Manajemen Waktu Kritis: 65 menit pada Sintaks 4 sangat padat; kendala massal jaringan internet saat registrasi/autentikasi GitHub berisiko membuat tahap push meleset.

💭 Refleksi

Menyusun rancangan ini membuka kesadaran saya bahwa merancang kelas kejuruan IT tidak hanya tentang mengajar urutan perintah terminal, melainkan mendesain ekosistem belajar yang meniru alur kerja industri. Saya belajar pentingnya menyediakan perancah (scaffolding) yang kuat serta memperhitungkan variabel teknis laboratorium (koneksi internet dan potensi galat) agar sintaks PjBL berjalan lancar.

🖥️ Media Pembelajaran (PPT & Bahan Ajar)

PPT sebagai visual anchor, Bahan Ajar sebagai handbook. Keduanya menggunakan analogi konkret "Save Point Game" untuk Git dan "Google Drive Khusus Kodingan" untuk GitHub. Struktur materi berfokus pada 3 area kerja (Working Directory, Staging Area, Local Repository) dan alur mutlak: EDIT → ADD → COMMIT → PUSH.

Kelebihan: visualisasi arsitektur jelas; edukasi kesadaran keamanan siber (larangan unggah file sensitif, perkenalan .gitignore); panduan troubleshooting prediktif (git is not recognized, fatal: not a git repository, push rejected).

Kekurangan: beberapa slide padat teks sehingga kurang terbaca dari baris belakang; minim visualisasi alur autentikasi GitHub browser saat pertama git push.

📝 LKPD

Berbasis panduan praktikum terpandu, dikombinasikan studi kasus otentik "Website Agensi PixelPlay". Terstruktur dalam 4 tahap: (1) Instalasi & Konfigurasi, (2) Repository Lokal & Commit Pertama, (3) Repository GitHub & Push, (4) Perubahan Proyek & Push Kembali. Dilengkapi kotak centang self-monitoring, 5 pertanyaan studi kasus, tabel Bukti Praktik, kuis, dan lembar refleksi.

Kelebihan: scaffolding kokoh via kotak centang; verifikasi hasil objektif (git --version, git remote -v, git log, tampilan repositori web); skenario bermakna sebagai Junior Web Developer.

Kekurangan: beban dokumen padat (instruksi + studi kasus + tabel bukti + 10 PG + 5 esai + refleksi) memicu cognitive overload; instruksi terlalu linier (cookbook style).

📊 Instrumen Penilaian

Triangulasi seimbang: Keterampilan/Praktik Kinerja (70%), Pengetahuan Tertulis (30%), dan Observasi Sikap/DPL deskriptif. Aspek praktik dibedah menjadi 9 kriteria terukur (instalasi, konfigurasi, commit, remote origin, push, kerapian, dst.). Pengetahuan diukur via 10 PG + 5 esai, dilengkapi lembar observasi DPL.

Kelebihan: pembobotan proporsional untuk SMK (70% praktik); rubrik objektif rinci skala 1–4 + tabel konversi; pedoman penskoran esai transparan.

Kekurangan: beban administrasi guru tinggi (9 aspek × 30+ siswa secara real-time); soal kuis dominan LOTS (C1–C2), minim HOTS berbasis analisis galat.

Siklus 4 — Sinkronisasi GitHub, Personal Access Token & Kolaborasi Tim

Model PjBL + Hands-on Lab · 2 × 45 menit (90 menit)

🔍 Analisis Mendalam

Modul dirancang untuk 90 menit (2 × 45 menit) menggunakan model Project Based Learning (PjBL) dengan strategi Hands-on Lab. Fokus utama: sinkronisasi repositori lokal ke remote GitHub, autentikasi berbasis Personal Access Token (PAT), dan alur kolaborasi tim.

✅ Kelebihan

  • Sintaks PjBL Adaptif: Apersepsi membumikan konsep remote repository via analogi "buku catatan pribadi di rumah" (lokal) vs "perpustakaan online" (GitHub).
  • Antisip

    ✅ Kelebihan

    • Sintaks PjBL Adaptif: Apersepsi membumikan konsep remote repository via analogi "buku catatan pribadi di rumah" (lokal) vs "perpustakaan online" (GitHub).
    • Antisipasi Masalah Autentikasi: Modul secara eksplisit mengedukasi peralihan password ke Personal Access Token (PAT), masalah paling umum dialami pemula saat push.
    • Kolaborasi Tim Nyata: Skenario kerja kelompok dengan pembagian peran (leader, developer, dokumentator) mencerminkan alur kerja industri.

    ⚠️ Kekurangan

    • Durasi Sangat Terbatas: 90 menit untuk sinkronisasi, pembuatan PAT, troubleshooting autentikasi, dan simulasi kolaborasi sangat padat.
    • Ketergantungan Koneksi: Proses push dan verifikasi repositori membutuhkan internet stabil; kendala jaringan langsung menghentikan praktik.

    💭 Refleksi

    Siklus ini mengajarkan saya bahwa konsep abstrak seperti remote repository dan autentikasi token perlu dijembatani dengan analogi yang dekat dengan kehidupan siswa. Saya juga belajar bahwa dalam kelas kejuruan IT, kesiapan infrastruktur (jaringan, akun GitHub aktif) adalah bagian dari perencanaan pembelajaran, bukan sekadar teknis belaka. Ke depannya, saya akan menyiapkan akun demo cadangan dan video tutorial singkat sebagai backup saat kendala jaringan muncul.

    🖥️ Media Pembelajaran (PPT & Bahan Ajar)

    Media berfokus pada visualisasi alur sinkronisasi (git remote add → git push), langkah pembuatan Personal Access Token di GitHub, serta diagram alur kolaborasi tim (fork/clone → branch → pull request). Dilengkapi tangkapan layar antarmuka GitHub dan panduan troubleshooting autentikasi.

    Kelebihan: langkah pembuatan PAT divisualkan bertahap; panduan penanganan galat autentikasi lengkap; diagram kolaborasi tim jelas.

    Kekurangan: materi padat untuk 90 menit; minim latihan mandiri terbimbing karena keterbatasan waktu.

    📝 LKPD

    Berbentuk panduan lab terpandu dengan skenario kolaborasi tim: setiap kelompok menyinkronkan proyek ke GitHub, membuat PAT, melakukan push, lalu mensimulasikan kontribusi anggota via branch. Dilengkapi kotak verifikasi (git remote -v, tampilan repositori), tabel bukti praktik, dan refleksi tim.

    Kelebihan: skenario kolaborasi autentik; verifikasi hasil objektif; refleksi tim mendorong komunikasi.

    Kekurangan: waktu terlalu singkat untuk seluruh tahapan; instruksi perlu dipangkas agar esensial.

    📊 Instrumen Penilaian

    Penilaian menekankan kinerja praktik (sinkronisasi berhasil, PAT terkonfigurasi, push terverifikasi) serta observasi kolaborasi tim (DPL: Kolaborasi & Kemandirian). Dilengkapi rubrik skala 1–4 dan lembar observasi kerja kelompok.

    Kelebihan: penilaian autentik berbasis bukti repositori; rubrik kolaborasi terukur.

    Kekurangan: sulit menilai kontribusi individual dalam kerja tim hanya dalam 90 menit.
